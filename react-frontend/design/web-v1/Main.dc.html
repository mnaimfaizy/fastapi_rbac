Designer assumptions and adjusted values

  • Input borders use #D1D5DB light / #4B5563 dark (both from the status table) instead of the border token, so fields read as fields.
  • Unchecked checkboxes, empty checklist circles and the switch-off track use text muted (#6B7280 / #9CA3AF) to reach 3:1 non-text contrast.
  • Table header text uses text secondary: text muted on muted is only 4.39:1 in light mode.
  • Dark danger solid #F87171 carries #0B1215 text; white on it is 2.8:1. The dark danger-outline button uses #FECACA text.
  • Danger menu items use the danger solid as text (4.83:1 light). Inline field errors use the locked-badge text #991B1B / #F87171, so no new values were added.
  • Dark auth brand panel uses primary subtle #134E4A with on-primary-subtle text. Full #2DD4BF was too loud next to a dark form.
  • Tooltips are inverted (text primary background). The “needs API” engineer tags use the warning pair with a dashed amber edge, so nobody mistakes them for UI.
  • Header carries a breadcrumb for wayfinding: quieter than repeating titles.
  • Password policy (confirmed): passwords expire every 90 days and “expiring” means within 14 days. Expiry isn’t enforced yet, so expiry data carries “needs API” tags.
  • Groups can nest (confirmed). Each tree shows one example child group, Support under Operational and Articles under Content, alongside the members.
  • Permission matrix sample: Manager holds its seeded 15 permissions, with 3 pending changes (user.delete and role.update added, content.delete_article removed). Every other screen shows 15.
  • Managers can assign only roles whose permissions they already hold, which in practice is User. The superuser switch shows only to superusers: admin forms are drawn as a superuser, and the switch carries a dashed “visible to superusers only” tag.
  • On mobile the users list becomes stacked rows. Tables keep to desktop and tablet.
