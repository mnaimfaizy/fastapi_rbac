# Create pull request

Canonical rules and the full failure table: [`docs/agents/pr-pipeline.md`](../../../docs/agents/pr-pipeline.md). Title format: [`docs/agents/commit-messages.md`](../../../docs/agents/commit-messages.md). Label allowlist: [`docs/agents/pr-labels.txt`](../../../docs/agents/pr-labels.txt).

## Who does what

| Step | Owner |
| --- | --- |
| Check the branch is not the base branch and is committed | You |
| Draft the title, labels, merge base and body | `pr-drafter` agent (read-only) |
| Write the body to a file and run the runner | You |
| Push, assign, and create or update the pull request | `bash scripts/development/pr-runner.sh` |
| Repair a failure the runner reports | You, or `pr-drafter` for a draft problem |

Never ask `pr-drafter` to push, create the pull request or edit files.

## Rules

- Never run `git push`, `gh pr create` or `gh pr edit` yourself. The only way to open or update a pull request is `bash scripts/development/pr-runner.sh`.
- Always pass `--title`, `--body-file` and `--merge-base` from the draft.
- When the user names a base branch, give the same one to `pr-drafter` and to the runner as `--base <branch>`. Otherwise both use `main`.
- The `MERGE-BASE:` line shows the drafter inspected the branch. If it is missing, send the draft back. Never compute the SHA yourself and add it, and never put a SHA in the drafter's prompt.
- If the runner refuses the AI notice, the `**Reversible:**` or `**Blast radius:**` line, or a closing keyword in backticks, send the draft back to `pr-drafter` with the runner's message. Do not fix the draft yourself.
- Pass each name on the `LABELS:` line with `--label`. Pass no `--label` when the line is absent, or when the user said not to label. Never add a label the draft did not choose, and never a workflow label (`agent:*`, `team:*`, `ready-for-*`, `needs-*`).
- Request a reviewer only when the user names one, with `--reviewer <login>`.
- Pass `--draft` only when the user, or the run's route (for example `orchestrate.config.yml`), asks for a draft.
- If the drafter fails, stop and report it. Do not open a pull request with a body built from commit subjects.
- There is no force-push. If the runner reports `diverged`, merge `origin/<branch>` (or `origin/main`) into the branch through the commit pipeline; never rebase pushed commits, and never run `git push --force`.
- Never merge the pull request, and never delete a branch. A person merges.
- Report the title and the pull request's URL. Do not paste the body back.

## Steps

1. Run `git status --short` and `git branch --show-current`. If the branch is the base branch, stop. If there are uncommitted changes the user means to ship, commit them first with the `commit-change` skill.
2. Run `git fetch origin <base>` so the merge base is computed against the current base.
3. Call `pr-drafter`, with the base branch when the user named one and any test results the user or you already have. Do not give it a merge base.
4. If it returns `ON_BASE_BRANCH:` or `NO_BRANCH_COMMITS:`, stop and report that line.
5. Split the draft: the `TITLE:` line, an optional `LABELS:` line, the `MERGE-BASE:` line, then the body from the `> *This was generated by AI.*` line. Write only the body to a temporary file outside the repository (for example under `/tmp`).
6. If there is no `MERGE-BASE:` line, stop and call `pr-drafter` again.
7. Run, and wait for it:

   ```sh
   bash scripts/development/pr-runner.sh --title "<title>" --body-file <path> --merge-base <sha>
   ```

   adding `--base <branch>` when the user named a base (the same one you gave `pr-drafter`), `--label <name>` for each label, `--reviewer <login>` for each reviewer the user named, and `--draft` when a draft was asked for.

8. On success, return the title and the URL the runner printed.
9. On failure, read the trailer at the end of the output and act on its `reason` (below), then run the same runner command again.

## Failure reasons

The runner ends every failure with a trailer: `pr-runner: failed`, `reason`, optional `scope` and `paths`, and `hint`.

| reason | What to do |
| --- | --- |
| `usage` | Fix the arguments the message names. |
| `auth` | `gh auth status`; fix the login before saying a pull request exists. |
| `on-base` | Create a branch per `docs/agents/branch-names.md`; do not open a pull request from `main`. |
| `merge-base` | Fetch the base, call `pr-drafter` again (same `--base`), retry with the new draft. |
| `no-commits` | Commit the work with `commit-change` first. |
| `body` | Header line left in the body file: rewrite the file. Missing AI notice or a closing keyword in backticks: send the draft back. |
| `risk` | Send the draft back to `pr-drafter` with the runner's message. |
| `label` | Drop the label, or send the draft back; never add the label to the allowlist to get past the runner. |
| `secret` | A branch commit adds a secret-looking path in `paths`. Stop and tell the user; remove it in a new commit only if they agree. |
| `diverged` | The remote branch has commits this one does not. `git merge origin/<branch>`, then retry. |
| `push`, `create` | Read the git or gh output above the trailer, fix the cause, retry. |

## Checks before you report

- The body file starts with the AI notice and holds no `TITLE:`, `LABELS:` or `MERGE-BASE:` line.
- Every label is on `docs/agents/pr-labels.txt`.
- The runner printed a URL. If it reported an authentication or push failure, the pull request does not exist yet.
