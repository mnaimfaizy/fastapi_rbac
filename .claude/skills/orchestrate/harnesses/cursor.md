# Cursor

- **Id:** `cursor`
- **Support Level:** `tried`. The first run (on `mnaimfaizy/fastapi_rbac`, pull request 339) found the gaps in mnaimfaizy/agent-kit#189 to #192: it had no Executor to follow, its building sub-agent shared the checkout, QA ran inside the building sub-agent, and a stale user-level copy of the skill was loaded.
- **Tier:** between 1 and 2. It starts sub-agents in the background and tells the Chief of Staff when one ends, but the human cannot talk to a sub-agent while it works.
- **Headless run:** `agent -p`
- **Headless QA:** yes, else a session the human starts.
- **Facts from:** cursor.com/docs, the Subagents, Worktrees, Skills, Headless and Run modes pages, read on 2026-11-14 with Cursor 3.28; and the first run. The waiting facts (`await` and the `stop` hook) are from the Subagents, Hooks and Agent overview pages and the CLI changelog, read on 2026-11-18 with Cursor 3.30.14.
- **Executors:** building and analysis, a background sub-agent in its own worktree; QA, a headless run of the Cursor CLI (`agent`), else a session the human starts.
- **Notify:** none known: the sources in **Facts from** name no way for the Chief of Staff to notify the human. A queued question waits in its session and on the board.

## Verbs

- `spawn`, for a building or analysis Delegation: a background Task sub-agent on the brief, with the plan's model, and a brief that opens by asking for its own isolated worktree on the Delegation's branch. Straight after `spawn`, check that the sub-agent's working directory is a worktree under `~/.cursor/worktrees/` on that branch. If it is the Chief of Staff's checkout, stop the sub-agent and raise it to the human before it writes anything. The handle is the agent id the Task tool returns.
- `message`: "Resume agent `<id>`: <text>", once the sub-agent has ended.
- `await`: a foreground watch inside the turn ([HARNESSES.md](../HARNESSES.md#waiting-an-event-and-a-heartbeat)). The Chief of Staff runs a shell loop in the foreground that checks every 60 seconds. It returns on any change to a Delegation's `report.md` or `decisions.md`, to `~/.cursor/subagents/`, or to the state of a pull request the run waits on, or else at a 10 to 15 minute cap. The foreground watch shell loop is strictly read-only (inspection and stdout only) and must never append to or write `activity.md`, `board.md`, or `events.jsonl`. Before launching each watch (and on `--resume`), the Chief of Staff increments a monotonic generation id in `<run_dir>/<run>/watch.gen` (and cleans up any prior `<run_dir>/<run>/watch.pid`), passes the generation id into the watch, and the watch checks it against `watch.gen` on each iteration and exits immediately if superseded. Any Chief of Staff turn that receives watch output whose generation id does not match current `watch.gen` drops it without acting or appending to `activity.md` or `events.jsonl`; at close-out or when the run parks, delete `watch.gen` and `watch.pid` alongside the heartbeat. Then the Chief of Staff acts on what changed, or on nothing, writes the board, and runs the watch again. The Chief of Staff never ends its turn while the run waits on a Delegation, so the run never depends on the editor waking an idle parent. A background sub-agent's end, where the editor announces it, is one more change the watch sees. The watch's cap is the heartbeat.
- The Dispatch Plan offers a `stop` hook heartbeat as a persistent change, made only on the human's yes. While a run is open, a project `stop` hook returns `followup_message: "Heartbeat: check the orchestrate board"`, so a turn that ends anyway is followed by another. The hook acts only while the run folder holds `heartbeat.marker`. The Chief of Staff writes the marker at the first `spawn`, with the heartbeat, when the human has said yes to the hook. It removes it at close-out and when the run parks (with any `watch.gen` and `watch.pid` files), which is how this harness deletes the heartbeat (SKILL.md steps 6 and 10), and `--resume` writes it again. Its `loop_limit` is a number the human approves with the hook, never `null`, so a marker left behind by a crash or an interrupted session cannot follow turns without end. It is the net under the watch, not a replacement for it: whether it can wait before it returns is a check before use item.
- `report`: the report file, by its absolute path; a Delegation whose write is refused ends with its report as its last message instead.
- A QA Delegation: the Chief of Staff makes its worktree, `git worktree add --detach <path> <head>`, with `<path>` outside `~/.cursor/worktrees/`, which Cursor cleans up. Then `agent -p "<brief>" --model <model> --output-format json` in that worktree, as a background process, with `message` as `agent -p "<text>" --resume <session-id>` there. Print mode refuses every write outside the workspace, so the QA run ends with its report as its last message, unless the human approved `--force` in the Dispatch Plan. If `-p` does not run `/qa-plan <n> [--answers <working_dir>/qa-readiness.json]`, or has no browser, fall back to a session the human starts in a worktree, where the human types `/qa-plan <n> [--answers <working_dir>/qa-readiness.json]` and later `/manual-qa <plan file>`. With `go`, that is the typed route; with `go autonomous`, on a `stack` or a `url` target, the same session follows its brief instead, reading each QA skill's `SKILL.md` from the paths the brief gives, so no command is sent or typed. A `url` target runs from the brief too, with its hosts typed in the Dispatch Plan and relayed through the brief.

## Limits

- A sub-agent shares the Chief of Staff's checkout unless the brief asks for isolation, and no Task parameter forces it. Each `spawn` is checked, and a sub-agent found in the checkout is stopped.
- The human can read a sub-agent's transcript, but cannot talk to it while it works.
- Cursor asks before an agent writes outside its workspace, so the human may be asked to approve each report written to the run folder.
- A sub-agent cannot subscribe to CI (refused in the first run), and a CI subscription does not deliver review comments. The Chief of Staff watches each pull request's checks and comments itself, with `gh`.
- Cursor deletes the oldest worktrees under `~/.cursor/worktrees/` once there are more than `cursor.worktreeMaxCount` (25 by default), including ones made by hand there. A Delegation pushes its branch as soon as it has a commit, and the Chief of Staff makes its own scratch worktrees outside that folder.
- On the typed route (with `go`), QA may fall back to a session the human starts, where the human types the two QA commands.
- While the run waits on a Delegation, the Chief of Staff's turn stays open on the foreground watch. A message the human queues there waits for the current task to finish, so to talk to the Chief of Staff mid-run, the human stops its turn. The Chief of Staff answers, then runs the watch again.
- A Cursor Cloud Agent can subscribe to its own pull request, but cannot reach the run folder or the local QA Stack, and needs a cloud plan; it is offered only when the human asks.
- Cursor Projects (beta) is never an Executor or the Chief of Staff. Its coordinator rewrites each brief, and no API setting picks a worker's model, branch or brief. Its local workers run in the existing checkout, with no isolation. Nothing it does reaches a local session as an event (read 2026-11-14).

## Check before use

- Whether a QA session accepts a host relayed through its brief: that it checks it again with `adapter.mjs host` before any sign-in, and holds its scenarios (never asks) when it refuses it. A harness whose session does not holds every scenario of a `url` target. Record what was found.
- Whether text can reach a sub-agent while it is still working.
- That the editor, and not only the CLI, announces a background sub-agent's end.
- Whether a finished background sub-agent or background shell starts a new turn in an idle parent, in the editor or the interactive CLI. The CLI changelog documents it for ACP mode only (not yet confirmed).
- How long a foreground shell command in the editor may run, and whether a long turn is cut off. The foreground watch depends on both (not yet confirmed).
- Whether a `stop` hook may wait minutes before it returns `followup_message`, and its default timeout, which the docs give only as "platform default" (not yet confirmed).
- Whether a worktree sub-agent's workspace is its worktree or the Chief of Staff's folder, and so whether its report write needs approval.
- Whether `-p` runs `/qa-plan <n>` as the user's own invocation, and whether a headless run has a browser.
- Which copy wins when both `~/.claude/skills` and `.claude/skills` hold `orchestrate`: Cursor loads both.
- Whether the harness can notify the human that a question is queued, and how: record what was found.
